# Team management

Your team now contains the active four slots and an owned-copy inventory. The separate training card, tier selection, automatic replacements and eligible-replacement list are removed. Website engine instances clear those legacy settings at startup and whenever settings or old profiles are applied.

Auto level-up is a single switch in the active-team header. It saves immediately and trains only the active team using earned XP, one level per cycle up to 35, between hunting/campaign encounters. Per-copy platinum bonus switches are disabled unless auto level-up is on. Permissions follow individual copy IDs and never transfer to a different Miscrit placed in the same slot. Purchases are checked again after the free level-up: automation must still be running, the copy must still be active and selected, and the exact bonus cost must be 1 platinum. Missing balances, catch-up costs, rejected purchases or unconfirmed refreshed bonus/balance stop automation. No paid XP training or token training is added.

Inventory shows portraits, names, rarity, copy IDs, level, rating, current/max HP and XP. Search includes family names and copy IDs; rarity filters, sorting and 24-copy pagination preserve access to the complete roster. Green HP and blue XP use native progress elements. Fainted, max-level and unavailable values are explicit. HP follows the shipped PlayerMiscrit formula, adding bonus and equipped relic HP. Unknown equipped-relic effects produce an unavailable maximum rather than a guessed value.

Native drag/drop replaces an occupied slot or swaps two active teammates. Keyboard and touch users can select a copy, then choose a slot. Each request carries the displayed team order; the backend refreshes first and rejects stale orders or new battles. It sends one native update_team request, refreshes again and verifies the complete order. Unconfirmed saves block further changes. Running automation, battles, arena drafts/queues, reconnection and pending requests block swaps. Owner-cookie, origin and CSRF checks apply to both new local endpoints.

Backend health version 17 exposes teamManagementVersion 1. Finish any active battle, stop the website backend and launch it again after updating. The UI explains this requirement when an older backend is running.

Validation uses local fixtures with no game login or live currency purchases: Node tests cover HP calculation, copy permissions, legacy-setting retirement, native team saves, stale/concurrent requests, purchase guards and endpoint access checks. Browser tests cover immediate toggles, real bars, duplicate copies, search/pagination, actual drag gestures across scrolling, stale-save errors, themes and mobile slot selection. Preview screenshots in validation/team-inventory-*.png use a fixture account.
